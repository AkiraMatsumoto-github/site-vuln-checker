# サイト脆弱性チェッカー（Site Vulnerability Checker）

[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)
[![CI](https://github.com/AkiraMatsumoto-github/site-vuln-checker/actions/workflows/ci.yml/badge.svg)](https://github.com/AkiraMatsumoto-github/site-vuln-checker/actions/workflows/ci.yml)
![Chrome: Manifest V3](https://img.shields.io/badge/Chrome-Manifest%20V3-4285f4.svg)
![無料](https://img.shields.io/badge/%E6%96%99%E9%87%91-%E7%84%A1%E6%96%99-brightgreen.svg)

**開いているサイトが、何で動いていて、どこが古いか。ひと目で。**

ブラウザでサイトを開いて、アイコンを押す。すると、そのサイトが使っている部品（WordPress 本体、
追加機能、JavaScript のライブラリ）と**バージョン**を推定し、**直したほうがよいもの**だけを
一覧で出します。判定はお使いのパソコンの中で行い、**見ているサイトの URL を外部へ送りません**。

**いま対応しているのは WordPress のサイトです**（本体・追加機能・テーマ・JavaScript ライブラリ）。

## いま、何が困るのか

1. **古い追加機能に気づけない。** WordPress のサイトは、本体・追加機能（プラグイン）・テーマ・
   JavaScript のライブラリが組み合わさって動いています。どれか 1 つでも古いと弱点になりますが、
   外から見ても分かりません。
2. **「どこから直すか」が分からない。** 更新すべきものが 20 個あったとき、全部を同じ優先度で
   直すのは現実的ではありません。
3. **情報が英語で、あちこちに散っている。** 脆弱性の情報（NVD、JVN、各ベンダーのデータベース）を
   1 つずつ開いて、自分のサイトのバージョンと突き合わせる作業は手間がかかります。

## 既存の道具では、なぜ足りないのか

どれも用途がはっきり違います。**「ブラウザで見ているサイトを、その場で」見る道具**がありません。

| 道具 | 何のためのもの | この用途で足りない点 |
| --- | --- | --- |
| [WPScan](https://wpscan.com/)（CLI） | WordPress サイトを詳しく調べる専門ツール | ターミナルから URL を指定して実行し、レポートを作る道具。**ページを見ながらその場で**使う形ではない |
| Wordfence / Patchstack（WordPress プラグイン） | 自分のサイトを守る | **自分のサイトにしか入れられない**。見ている他人のサイトは調べられない |
| [Retire.js](https://github.com/RetireJS/retire.js) | JavaScript ライブラリの既知の弱点を検出 | **JavaScript ライブラリだけ**。WordPress 本体や追加機能は見ない |
| [OSV-Scanner](https://google.github.io/osv-scanner/) | 手元のコードが使っている部品を調べる | **手元のソースコードが前提**。公開されているサイトは対象外 |
| NVD / JVN を直接見る | 一次情報（最も正確） | 英語・大量・サイトとの対応付けが手作業になる |

## このツールの答え

上の表の空いているところ（**その場で・複数の層をまとめて・直す順番つきで**）を埋めます。

- **1 クリックで調べる。** ページを開いてアイコンを押すだけ。**既定では追加のリクエストを送りません**
  （PHP の版を読みたいときだけ、サイトごとに許可して HEAD を 1 回）。
- **材料を 1 か所に集める。** バージョン、該当する弱点、直したバージョン、悪用された実績を
  まとめて出します。
- **「古い」も指摘する。** 弱点が 0 件でも、サポートが終わった枝（PHP 8.1 など）は「移行が必要」と出します。
- **分からないものは「分からない」と出す。** バージョンが取れないときに「問題なし」とは言いません。
  PHP やフレームワークの版が分かる場合は、画面から入れて判定できます。

## 分かること / 分からないこと

| | 内容 |
| --- | --- |
| ✅ 分かる | WordPress で作られているか／**本体のバージョン**／追加機能（プラグイン）の名前とバージョン／テーマ／JavaScript ライブラリ／**該当する弱点と、直したバージョン**／**サポート終了（EOL）** |
| ✅ サイトが公開していれば分かる | **PHP のバージョン**（`X-Powered-By` を出しているサイト。実測 **10 サイト中 1 サイト**）。**初回のチェック時に許可を求めます**（拒否しても判定は続きます） |
| ✅ 入力すれば分かる | 公開していないサイトの **PHP・フレームワークのバージョン**。分かる場合だけ画面から入れてください |
| △ 半分だけ | 追加機能は**画面に読み込まれているもの**だけ。バージョンが取れないものは「灰」になります |
| ✕ 分からない | サーバーが公開していない PHP の版／管理画面の中でだけ動く追加機能／サービスのサーバー側／**「安全である」こと** |
| 🚧 これから | 自分のサイトを詳しく読み取る機能（管理画面の「サイトヘルス」）／Chrome Web Store での公開 |

## 使い方（2 ステップ）

1. 調べたいサイトを開いて、**ツールバーのアイコン**をクリック。
2. サイドパネルの **「このサイトを調べる」** を押すと、**更新すべきもの**が出ます。

**URL を入力する必要はありません。** サイトの URL は開いているタブから自動で取り、
「弱点の一覧表（索引）」も**初回のクリックで自動的に**読み込みます（初回だけ Chrome が
アクセス許可を確認します）。

**PHP のバージョンが分かる場合**は、サイドパネルの「バージョンを入力」に `8.1.27` のように入れて
**追加**を押してください（サイトごとに保存されます）。サポート終了と、PHP 本体の弱点を判定します。

> サイトが `X-Powered-By` を公開している場合は、**初回のチェック時にそのサイトへの許可を求める**ので、
> 許可すれば入力なしで読めます（拒否しても判定は続きます）。


## どうやって「危険」を決めているか

判定は 2 段階です。

**1. そのバージョンに、直っていない弱点があるかを調べる**

公開されている弱点の「影響を受けるバージョン」と、検出したバージョンを比べます。
該当すれば、直したバージョン（例: `→ 5.9.9 へ更新`）を出します。

**2. 該当したものの大きさを、3 つの材料で決める**

| 材料 | どこから来る値か | このツールでの扱い |
| --- | --- | --- |
| **悪用された実績**（KEV） | 米 CISA が公開する一覧に、その弱点の番号が載っているか | 載っていれば **赤** |
| **悪用される確率**（EPSS） | 米 FIRST が毎日公開する予測値（0〜100%） | **50% 以上**なら赤 |
| **深刻度**（CVSS） | 米 NIST が弱点ごとに付けた 10 点満点のスコア | **9.0 以上**なら赤 |

**どれも提供元の値をそのまま使い、このツールで計算し直してはいません。** 9.0 と 50% は
「このツールが赤とみなす線」です。CVSS 9.0 以上は提供元の区分で「Critical（緊急）」。
EPSS 50% は、実際に測った WordPress の弱点では中央値が 0.30% だったので、**よほど高い値**です
（1 年分の索引で 50% 以上は 6 件だけでした）。

**3. 4 段階で表示する**

| 表示 | 意味 | どうすればいいか |
| --- | --- | --- |
| 🔴 赤 | 実際に悪用された、または悪用されそうな弱点がある | できるだけ早く更新する |
| 🟡 黄 | 弱点はあるが、悪用の兆候はまだない | 次の更新で対応する |
| ⚪ 灰 | バージョンが分からず、判定できない | 管理画面などでバージョンを確認する |
| — | 弱点はあるが、すでに修正版以降 | 対応は不要 |

**「緑（安全）」は使いません。** バージョンが分からないものを「問題なし」と表示すると、
かえって危険だからです。代わりに「灰（判定できない）」と出します。

**赤になるのは、3 つの材料のどれか 1 つでも当てはまったとき**です（3 つ全部そろう必要はありません）。
1 年分の索引では KEV は 0 件でしたが、**深刻度 9.0 以上が 380 件**、**悪用確率 50% 以上が 6 件**
（うち 5 件は両方に該当）あり、**赤は 381 件**になりました。
**KEV が 0 でも、深刻度か悪用確率で赤になります。**

（出てくる用語は、末尾の[用語](#用語)にまとめています。）

## 判定の根拠：外から何が分かるのか

**外から分かるのは「ページが読み込んでいるファイルの URL」と「`<meta>`」だけ**です。
WordPress は本体も追加機能もバージョンを URL に出す（`?ver=6.8.2`）ので取れます。
PHP はサーバー側の設定で、公開していないサイトが多いため取れません。
だから PHP は「取得できたときだけ警告し、分からなければ『不明』」と出しています。

### 索引（弱点の一覧表）について

索引は**既定で直近 1 年**です。NVD の API は 1 回の期間指定が **120 日まで**なので、
**120 日ずつ 4 回に分けて取得して積み上げます**。全期間が必要なときは `--all`、
日々の更新は `--days 14 --merge` で差分だけ足します。

直近 1 年で作った索引の実測値です。

| 項目 | 結果 |
| --- | --- |
| 索引の大きさ | **6,149 件**（6,115 の CVE）／2.6 MB |
| 影響範囲の書き方 | 「X 以下」4,438 件 ／ 「X より前」1,711 件 → **約 7 割が「X 以下」** |
| 実際に悪用された弱点（KEV） | **0 件** |
| 悪用される確率（EPSS） | 99% に付与。**中央値 0.30%** ／ 最大 76.2% ／ **50% 以上は 6 件** |
| 判定 | 赤 381 件 ／ 黄 5,768 件 |

**分かったこと**は 3 つあり、いずれも実装に反映しています。

**1. 影響範囲の書き方が 2 通りあり、「X 以下」が 7 割**

NVD の本文には、直したバージョンの書き方が 2 通りあります。たとえば Gravity SMTP の弱点はこうです。

> … is vulnerable to Sensitive Information Exposure **in all versions up to, and including, 2.1.4**.

これは「**2.1.4 以下**が影響」という意味です。「`before 2.1.5`」（＝ 2.1.5 **未満**）とは書き方が別で、
**`before X` だけを読む実装では、この弱点を索引に載せられません。** 載らないと、その追加機能を使っている
サイトでも「該当なし」と表示されます（＝ 危ないのに安全に見える）。

1 年分では **4,438 / 6,149 件（72%）** がこの「X 以下」の書き方でした。`before X` だけを読む実装だと
索引は **1,711 件（28%）** まで減り、**7 割の弱点を見逃します**。だから両方に対応しています。

**2. WordPress 追加機能は KEV に載らない**（0 件）。「実際に悪用されたか」だけでは WordPress を守れないので、
深刻度と「直したバージョンがあるか」を判定の中心にしました。

**3. EPSS でしか拾えないものがある**

悪用確率（EPSS）50% 以上は 6 件でした。うち 5 件は深刻度も 9.8 なので、**1 件は EPSS がないと赤になりません**
（上の Gravity SMTP: 深刻度 7.5 / 悪用確率 73.8%）。3 つの材料を併用する意味がここにあります。

> 索引は**全期間にできますが、既定は 1 年**です。何年も前の弱点は、すでに更新されていることが多く、
> 毎回すべてを取り直すのは時間の無駄になるためです。

## 実際の表示（例）

PHP 8.1.27 のサイトを調べ、バージョンに `8.1.27` を入力した場合です。

```
🔴 PHP  8.1.27
   → 8.5.12 以降へ移行 / → 8.2.35 へ更新
   2025-12-31 にサポート終了（8.1 系に修正版は提供されません）
   CVE-2026-109618  CVSS 9.2
   CVE-2026-109619  CVSS 9.2

— WordPress  6.2.6
   → 6.2.15 へ更新（同一系統）
   同一系統の最新は 6.2.15（パッチ未適用の可能性）
```

**同じ「赤」でも、直し方が 2 種類ある**ことが伝わるようにしています。

- `8.2.35` … その弱点を直した版（ただし 8.2 系もまもなく終了）
- `8.5.12` … サポート中の最新。**長く使うならこちらへ移行**

## 仕組み

索引を作る部分（Python）と、判定する部分（Chrome 拡張）に分かれています。

```
extension/                     Chrome 拡張（ビルド不要）
  detector.js                  部品とバージョンの推定
  advisor.js                   索引との照合と赤 / 黄 / 灰
  background.js                タブの情報収集 → 判定 → アイコンの色
  sidepanel.html / .js         結果の表示
  options.html / .js           索引 URL の設定
src/site_vuln_checker/         索引を作る側（Python 3.14 / uv）
  ingest.py                    NVD → 索引（「X より前」「X 以下」を読み取る）
  enrich.py                    悪用実績（KEV）・悪用確率（EPSS）の付与
  detect.py / advisories.py    判定ロジック（拡張の JavaScript と同じ仕様）
  survey.py / report.py        外部判定の実測と HTML レポート
tests/                         テスト用のデータ（**Python と JavaScript で共用**）
```

判定ロジックは Python と JavaScript の**二重実装**ですが、**同じテストデータで同じ結果**になることを
固定しています（Python 95 件 / JavaScript 20 件）。

## インストール

いまは Chrome Web Store で公開していません。開発版として読み込みます。

### 1. 弱点の一覧表（索引）を作る

```powershell
git clone https://github.com/AkiraMatsumoto-github/site-vuln-checker.git
cd site-vuln-checker
uv sync

# 索引を作る（既定は直近 1 年。NVD の都合で 120 日ずつ 4 回に分けて取得します）
uv run svc-ingest --out out/advisories.json
# PHP 本体・フレームワークの弱点を足す（NVD の CPE から。範囲がそのまま取れます）
uv run svc-ingest --source cpe --products php,wordpress,laravel,symfony,cakephp,django,rails `
  --merge --out out/advisories.json
# 悪用実績（KEV）と悪用確率（EPSS）を足す
uv run svc-enrich --index out/advisories.json
# サポート終了（EOL）を足す
uv run svc-eol --out out/advisories.json

# 全期間（2005 年以降）にしたいときは --all（数分かかります）
# 2 回目以降は差分だけ足す（例: 直近 14 日）
uv run svc-ingest --days 14 --merge --out out/advisories.json
uv run svc-enrich --index out/advisories.json
```

> `--source cpe` は NVD の CPE（構造化データ）から「どの版からどの版まで」を取ります。
> 本文の言い回しに左右されないので、PHP 本体やフレームワークはこちらが確実です。
> なお NVD は 1 ページを大きくすると 503 を返すため、50 件ずつ取得します（数分かかります）。


### 2. 索引を配信する（別のターミナル）

```powershell
python -m http.server 8000
```

### 3. 拡張を読み込む

1. `chrome://extensions` を開く
2. 右上の **デベロッパー モード** を ON
3. **パッケージ化されていない拡張機能を読み込む** → `extension` フォルダを選ぶ
4. 調べたいサイトを開いてアイコンをクリック → **「このサイトを調べる」**

初回のクリックで、索引の配信元（`http://localhost:8000`）と調べるサイトへの許可を確認されます。
**許可すれば、URL の入力は一切不要**です。索引の URL を変えたいときだけ、サイドパネルの
**設定** から指定してください（既定値が入っています）。

> **閲覧したサイトの URL はどこにも送りません**（通信は索引の取得だけです）。

## 設定（任意）: NVD の API キー

索引を作るとき、NVD の API はキー無しでも使えますが、**キーがあると 10 倍速く**なります
（30 秒あたり 5 回 → 50 回）。取得は無料です
（[NVD の申請ページ](https://nvd.nist.gov/developers/request-an-api-key)）。

```powershell
$env:NVD_API_KEY = "取得したキー"   # そのセッションだけ
setx NVD_API_KEY "取得したキー"     # 以後ずっと（新しいターミナルから有効）
```

リポジトリ直下の `.env` に書くこともできます（`.gitignore` 済み。`.env.example` をコピー）。
優先順位は**環境変数 → `.env`** です。**拡張にはキーを持たせません。**

## プライバシー

- 判定は**お使いのパソコンの中**で行います。**見ているサイトの URL を外部へ送りません**。
- 通信は**索引の取得だけ**です（どのサイトを見たかの情報は含まれません）。
- 拡張に **API キーなどの秘密情報を持たせていません**。
- アクセス解析・テレメトリはありません。
- 索引はパソコンに保存するので、一度読み込めばオフラインでも判定できます。

## 注意点

| 項目 | 内容 |
| --- | --- |
| **PHP のバージョンは分かりません** | サーバーが公開していないことが多いため（実測 4 サイト中 0）。分からないときは「不明」と表示します |
| 管理画面の中だけで動く追加機能は対象外 | ページに読み込まれないため |
| 「有効 / 無効」は断定しません | ページの本文に名前があるだけのものは「検出した」と表示します |
| 誤検知・見逃しはあります | バージョンの表記は書き換えられることがあり、セキュリティ製品がバージョンを隠すこともあります |
| 調べる範囲 | ページを開いたときに**読み込まれる情報だけ**。**既定では追加のリクエストを送りません**（PHP の版を読む設定にしたサイトだけ HEAD 1 回・本文は取得しません） |
| 判定は**推定**です | 安全性を保証しません。「灰」は「安全」ではありません |
| サポート終了の判定 | PHP・WordPress・Laravel・Symfony・Django・Rails・CakePHP・jQuery に対応（[endoflife.date](https://endoflife.date/) の公開データ）。CodeIgniter はデータ提供がないため未対応です |
| PHP の版は入力式 | サーバーが公開していないため、分かる場合だけ画面から入れてください |
| 異議申立ての窓口は未設置 | 公開（Chrome Web Store）までに用意します |

## よくある質問

<details>
<summary>無料ですか？</summary>

無料です（MIT ライセンス）。NVD / CISA KEV / FIRST EPSS など**公開データだけ**を使っています。
</details>

<details>
<summary>「灰」が多いのですが</summary>

バージョンが取れない部品です。追加機能が `?ver=` を付けていない、CSS / JavaScript が
まとめられている、といった理由があります。**推測で埋めずに「灰」**にしています。
</details>

<details>
<summary>「赤」が出たけど、たぶん誤検知です</summary>

「根拠」に、どの情報で判定したか（`meta:generator`、`asset:?ver=5.9.8` など）を出しています。
改善に使うので、[Issues](https://github.com/AkiraMatsumoto-github/site-vuln-checker/issues) で
教えてください。
</details>

<details>
<summary>PHP のバージョンはどうやって調べますか？</summary>

サーバー上で `php -v` を実行する、WordPress なら「ツール → サイトヘルス → 情報 → サーバー」を見る、
レンタルサーバーの管理画面で確認する、などの方法があります。分かったらサイドパネルの
「バージョンを入力」に入れてください。**そのサイトのぶんだけ**保存されます。
</details>

<details>
<summary>サポート終了（EOL）とは何ですか？</summary>

「もう修正版が出ない状態」のことです。たとえば **PHP 8.1 は 2025-12-31 で終了**しているので、
弱点が見つかっても 8.1 系には直した版が出ません。このツールは「弱点が 0 件」でも、
終了した枝を使っていれば**移行**をおすすめします。
</details>

<details>
<summary>WordPress 以外のサイトは対応していますか？</summary>

いまは WordPress のサイトだけです。Shopify は「読み込まれている JavaScript ライブラリ」までを
今後対応します。サービスのサーバー側（アプリのバージョンなど）は外部から見えないため対象外です。
</details>

<details>
<summary>Chrome Web Store ではいつ公開されますか？</summary>

説明文・プライバシーポリシー・異議申立て窓口を用意してからです。それまでは上の手順で使えます。
</details>

<details>
<summary>索引はどのくらいの頻度で更新すればいいですか？</summary>

拡張は 24 時間ごとに自動で取り直します。手動で更新したいときは、設定の「今すぐ更新」を押してください。
</details>

## 用語

| 用語 | 意味 |
| --- | --- |
| コア（本体） | WordPress 本体 |
| プラグイン（追加機能） | WordPress に機能を足す部品 |
| テーマ | サイトの見た目の型 |
| CVE | 弱点に付く世界共通の番号（例: `CVE-2026-12345`） |
| **CVSS（深刻度）** | 弱点の重大さを 10 点満点で表したもの |
| **KEV** | 実際に悪用されたことが確認された弱点の一覧（米 CISA が公開） |
| **EPSS（悪用確率）** | 30 日以内に悪用される確率の予測（0〜100%） |
| 索引 | このツールが使う「弱点の一覧表」（JSON ファイル） |
| パッシブ（受動的） | 追加のリクエストを送らず、すでに読み込まれた情報だけを見ること（このツールは**既定でパッシブ**。PHP の版を読む設定にしたサイトだけ HEAD を 1 回送ります） |
