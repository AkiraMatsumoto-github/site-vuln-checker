# 設計: 判定の言い回し（攻撃の可能性 / 攻撃時の影響度）

状態: **承認済み**（2026-10-30。`攻撃の可能性 = 実績あり / 特大 / 大 / 中 / 微 / 不明`、
`攻撃時の影響度 = 特大 / 大 / 中 / 微 / 不明` で確定）
対象: 拡張のサイドパネル（`extension/sidepanel.js`）、HTML レポート（`src/site_vuln_checker/report.py`）、
判定理由の文（`extension/advisor.js` / `src/site_vuln_checker/advisories.py`）

## 1. 課題

現在の表示は数字と略語だけで、意味が伝わらない。

```
CVE-2026-109618 ｜ 7.3.0 〜 8.2.35 未満が影響 ｜ 深刻度 9.2 ｜ 実際に悪用あり ｜ 悪用の可能性 100%
```

| 問題 | 内容 |
| --- | --- |
| 満点が分からない | `9.2` が 10 点満点なのか 100 点満点なのか分からない。「5 は高いのか」も判断できない |
| 用語が専門的 | CVSS / EPSS / KEV は一般用語ではない |
| 数字の意味が誤解される | 「悪用の可能性 100%」は *このサイトが 100% 攻撃される* ように読める（実際は「今後 30 日以内に悪用されると予測される確率」で、四捨五入で 100 に見えているだけ） |
| 文字数が多い | 「実際に悪用されています」だけで 12 文字。1 件あたりの行が長く、一覧で読めない |

## 2. 方針

**2 軸を、専門用語なしの 1 語で示す。** 数字（CVSS / EPSS）と略語は画面に出さない。

| 軸 | 意味 | 出す言葉 |
| --- | --- | --- |
| 攻撃の可能性 | 実際に悪用されているか／されそうか | 実績あり / 特大 / 大 / 中 / 微 / 不明 |
| 攻撃時の影響度 | 攻撃が成功したときの大きさ | 特大 / 大 / 中 / 微 / 不明 |

- 赤・黄の判定に使っている線（CVSS 9.0、EPSS 50%）と**同じしきい値**を使う。
  → 「なぜ赤なのか」と「表示の言葉」が食い違わない。
- 数値は README と企画書（根拠の説明）に残す。**画面からは消す**。

## 3. しきい値

### 攻撃の可能性（`exposureLabel`）

| 表示 | 条件 | 元データ |
| --- | --- | --- |
| 実績あり | 実際に悪用された事例が確認されている | KEV 登録あり |
| 特大 | 30 日以内に悪用されると予測される確率 50% 以上 | EPSS ≥ 0.5 |
| 大 | 同上 10% 以上 | EPSS ≥ 0.1 |
| 中 | 同上 1% 以上 | EPSS ≥ 0.01 |
| 微 | 同上 1% 未満 | EPSS < 0.01 |
| 不明 | 情報が無い | KEV なし・EPSS なし |

- **「実績あり」を最上位**にする（予測より、実際に悪用された事例のほうが強い根拠）。
  括弧書きをしないぶん短く、意味は凡例で補う（「実際に悪用された事例が確認されているもの」）。
- **不明を「微」にしない**（情報が無いものを「低リスク」と誤解させない）。

### 攻撃時の影響度（`impactLabel`）

| 表示 | 条件（CVSS） |
| --- | --- |
| 特大 | 9.0 以上 |
| 大 | 7.0 〜 8.9 |
| 中 | 4.0 〜 6.9 |
| 微 | 3.9 以下 |
| 不明 | CVSS なし |

> 影響度は「特大 / 大 / 中 / 微」の 4 段階。可能性の「微」と同じ字を使うが、
> **軸が違う**（凡例で 2 軸を並べて示す）。

## 4. 表示（案）

### 4.1 勧告 1 件（`details` の中）

```
CVE-2026-109618 ｜ 7.3.0 〜 8.2.35 未満が影響
攻撃の可能性 実績あり ｜ 攻撃時の影響度 特大
```

- **2 行**（現行 3 行 → 1 行削減）。「攻撃の可能性」「攻撃時の影響度」の順で固定。
- 修正版が範囲から自明でない場合のみ `｜ 8.2.35 で修正` を 1 行目に足す（現行どおり）。

### 4.2 カードの要約（`note`）

| 状況 | 文 |
| --- | --- |
| KEV あり | `攻撃の可能性: 実績あり` |
| EPSS ≥ 50% | `攻撃の可能性: 特大` |
| それ以外で CVSS あり | `攻撃時の影響度: 特大` |
| どれも無い | `弱点の影響を受けます`（現行どおり） |

### 4.3 パネル上部の凡例（新規）

> 赤・黄は「**攻撃の可能性**」（実績あり ＞ 特大 ＞ 大 ＞ 中 ＞ 微）と「**攻撃時の影響度**」（特大 ＞ 大 ＞ 中 ＞ 微）で決めています。
> 「実績あり」は、実際に悪用された事例が確認されているものです。

## 7. 整合性の担保

- **JS と Python の判定理由（note）が一致**することは既存の `tests/test_parity.py` が検証する（同じ索引・同じ入力で比較）。
- 単体テストで境界値を固定（`9.0` は特大、`8.9` は大、EPSS `0.5` は特大、`0.01` は中、`EPSS なし` は不明）。
- docstring では全角の `／` を使わない（ruff `RUF002` が「曖昧な文字」としてエラーにする）。

## 8. 決定事項（2026-10-30 確認済み）

1. 軸の名前: **攻撃の可能性** / **攻撃時の影響度**
2. 言葉のセット:
   **攻撃の可能性 = 実績あり / 特大 / 大 / 中 / 微（/ 不明）**、
   **攻撃時の影響度 = 特大 / 大 / 中 / 微（/ 不明）**
3. 情報が無いものは **`不明`** と出す（行は消さない。無いことを隠さない）
4. 数値（CVSS / EPSS）は**画面に出さない**（README・企画書には根拠として残す）
5. KEV は **`実績あり`** と表記（括弧書きしない。意味は凡例で補う）
