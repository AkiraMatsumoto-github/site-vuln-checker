# 実装レビュー（v0.11 時点）

対象: `extension/`（MV3 拡張）、`src/site_vuln_checker/`（索引生成 CLI）、`.github/workflows/`
方法: 全ソースを通読し、**実際に動かして**確認（Node のスタブで拡張の処理を再現、Python のテスト、
実サイト 2 件、公開中の索引）。テストは Python 121 / JS 41 件。

## 0. このレビューで直したもの

| # | 重大度 | 内容 | 対応 |
|---|---|---|---|
| 1 | **High** | **同じ CVE の影響範囲が 1 つしか表示されない**。CPE 由来の勧告は系統ごとに別レコード（PHP2Shell は 8.2/8.3/8.4/8.5 の 4 つ）だが、ID で 1 件に丸めていたため「8.2.35 未満」だけが出て、8.4 系の利用者が自分の Version を照合できなかった | 丸めるときに**全範囲を `ranges` として保持**し、画面で「A / B / C」と並べる。実測で 4 範囲が出ることを確認 |

## 2. 確認したが問題なかった点

- **プライバシー**: 閲覧 URL を送らない／索引の取得だけ。`tabs` は URL 取得のため（README に明記）
- **権限**: `sidePanel` / `activeTab` / `tabs` / `scripting` / `storage` / `alarms` のみ。`<all_urls>`・`webRequest` は要求しない
- **リモートコードなし**: 取得するのは JSON データのみ（MV3 ポリシー適合）
- **XSS**: 画面の文字列はすべて `textContent`（ページ由来の値を HTML として解釈しない）
- **失敗時の挙動**: 索引が取れない／サイトが読めない場合も、保存済みで判定を続け理由を表示
- **ETag 再確認**: 5 分間隔・304 で本文なし（実測）
- **二重計上なし**: WordPress の `generator` は core のみ（platform と重複しない）
- **空入力・壊れた索引**: 例外で落ちず、案内メッセージを出す
